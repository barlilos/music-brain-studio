# 006 — Living Progress Graph (R1, first vertical slice)

**Branch:** `feature/living-progress-graph`, from `design/living-progress-graph` (handoff 003).
**Status:** implemented and verified at code level and in a headless renderer preview.
**Not yet evaluated hands-on by the product owner, and not accepted.**

## Goal

Make the graph the primary experience. A user opens Music Brain Studio, enters a domain, sees
its branches, opens and edits a task, completes it, and sees the containing region visibly
reflect that completion. It should feel like working inside a living map of their projects,
not like managing rows in a productivity tool.

The visual reference is artboard **R1** of
[design exploration 02](../handoffs/003-living-progress-graph.md). R1 draws seeing with A's
seed bubbles and doing with B's unfold-in-place panel.

## Architecture decisions

1. **Explicit levels, no continuous zoom** (003 §5). A place has two parts:
   - the **focus**: the hub, which is `null` for the brain map;
   - the **unfolded branch**: one child of the focus, opened into a panel.

   `graphNavigation.ts` holds the pure rules: reveal, up, fold, focus, and reconcile after
   edits. Selection is the existing `editing.inspecting`, so the graph, the context menu and the
   Explorer drawer all open the same Inspector.

2. **Deterministic geometry, no force simulation and no new dependency.** `graphLayout.ts` is
   pure arithmetic and returns the same picture for the same tree:
   - sunflower seeds (golden angle);
   - greedy circle packing;
   - a ring sized by arc slot;
   - a fit-to-pane step with no minimum scale, so nothing is ever clipped.

   It renders as plain SVG plus HTML labels. React Flow is not used for the map: there are no
   edges to route and no nodes to drag, and the map needs exact control over nested circles.

3. **One rule for seeds and counts.** A seed is a leaf that carries a status. That is exactly
   what `summarizeProgress` counts, so the seeds on screen always equal the printed numbers.
   This is tested over every domain of the fixture.

4. **Aggregation rules.** These are counts, never percentages, and are tested in
   `progress.test.ts`:
   - A branch counts every status-carrying leaf below it, at any depth. A branch itself is
     never a unit of work.
   - Done is printed first, as an absolute number (`18 done · 28 open`). Discovering work can
     only raise _open_; the green heart sits at the centre and new seeds land on the rim, so
     completed work never visibly shrinks.
   - `regionStateOf(summary, finishedAt)` returns one of four states:
     - `finished`: declared by the user;
     - `nothingOpen`: there is known work and all of it is done;
     - `open`;
     - `empty`.
   - `finished` wins and says how much is still open inside. `nothingOpen` is derived and
     reverts the moment work is added. **A parent never finishes itself.**

5. **Finished is a stored, declared field.** `finishedAt` (`YYYY-MM-DD`) is modelled
   throughout:
   - on `ProjectNode` and `ExplorerNode`;
   - in the codec, as a modelled key: it is written only when set, and reopening removes the
     key;
   - in the read-only adapter;
   - through one mutation, `setNodeFinished`.

   It is offered on branches only (any node that does not carry a work status), from the
   Inspector and the context menu. Nothing sets it as a side effect. This **provisionally
   answers 002/003 decision 7**; the owner may narrow it to projects.

6. **"New" means added this session.** The file records no creation dates, and decision 4
   (where "last looked" is stored) is still open. So the amber ring marks nodes created since
   this file was opened. The set lives in `WorkspaceProvider`, writes nothing, and resets when
   another file opens.

7. **Seeds are for seeing, rows are for doing.** Hovering a seed names the task and its path.
   A click anywhere on a bubble opens it, seeds included. Clickable seeds were tried and
   dropped: clicking a bubble's centre hits its green heart, which selected a task by accident.
   One click unfolds and a double click re-roots. The unfold waits out the double-click
   interval (230 ms), so the second click cannot land on the panel that replaced the bubble.

8. **Context is preserved by layout, not by memory.**
   - When a branch unfolds, its siblings move onto a left-hand arc and stay clickable.
   - Labels that would collide on that arc are dropped in favour of a hover tooltip.
   - Every element is keyed by node id and glides with a CSS transition (380 ms, and none under
     `prefers-reduced-motion`).
   - Going up marks the branch you came from with a dashed ring.
   - When a selected node is moved, the view follows it.

9. **Dark by default** (003 decision 6). `<html class="dark">` drives Tailwind's `dark:`
   variants, so the M005 dialogs and Explorer match the graph's ground.

10. **The M005 surfaces stay reachable**, which provisionally answers 003 decision 5:
    - The Explorer is a drawer on the left rail.
    - The classic Explorer + Canvas split is the rail's bottom button.
    - Rename, retype, move, add, bulk add, notes, tags and status keep their M005 paths: the
      context menu, dialogs and Inspector.
    - Quick capture in the panel adds one task per Enter. Pasting several lines adds them all
      in one transaction.

### Deviations from R1

- **No minimap and no pinned ancestors.** The breadcrumb names the path, and every step but
  the last is a way back. A minimap mostly earns its place with continuous zoom, which was
  deferred.
- **Unfolded siblings use an arc of 100–260°, not 100–280°.** 280° swings right of vertical,
  into the panel's side; a test caught this.
- **No "New since your last visit".** Without a decision on where "last looked" is stored, the
  slice says "added this session" instead.
- **Inter is not bundled.** No new dependency was added, so the UI falls back to Segoe UI.

## Out of scope

AI import, conversation history, attachments, a search redesign, analytics, the journal,
drag-and-drop or freeform positioning, undo, delete, storage changes, persisting "last looked",
and composite views.

## Future considerations

- **Decision 4:** persist "last looked" per branch in app data, so "added this session"
  becomes "new since your last visit".
- **Decision 7:** narrow Finished to projects if the owner prefers. It is one predicate,
  `!isWorkItem` / `!showsStatus`, in the Inspector and the menu.
- **Remember the last place** (focus and unfolded branch) in app data.
- **Very wide branches.** A focus with dozens of child branches makes the ring large and the
  fit small. Labels stay readable, but bubbles shrink. A second ring or paging would help.
- **Retire the classic view** once R1 is accepted. `canvas/` and `shared/model/canvas.ts` can
  then be deleted.
- **Preview harness.** The headless preview (stub API + CDP) lived in the session scratchpad.
  If it proves useful it could become `scripts/preview/` as a fallback for when the isolated
  desktop guard refuses.
